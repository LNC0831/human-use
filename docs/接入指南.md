# Human Use v0.3 接入指南

默认路径为 npm 安装的 CLI + 用户级 Skill + 项目本机 API。软件安装一次，各项目独立保存数据和启动后台进程。正式 npm 包名尚待确认，本地安装包生成方式见 [部署与发布](部署与发布.md)。

## Codex 初始化

```powershell
human-use setup codex
```

setup 在 `~/.agents/skills/` 安装 human-use-setup 和 human-use。包装脚本指向已安装 CLI，当前项目无需安装依赖。不会覆盖同名非本工具管理的 Skill。更新 npm 包后再次 setup 刷新包装脚本。

必要时新开 Codex 会话，随后说“给当前项目引入 Human Use”。AI 应传入正确项目根目录执行 init。默认会启动后台服务、打开网页、合并项目说明与忽略项、生成 Codex hooks。

```powershell
human-use init --project E:/your-project --client codex
human-use status --project E:/your-project
```

`--no-hooks` 不生成 hooks；`--no-open` 不打开网页。重复 init 保留记录、复用服务。项目 human-use.json 可提交，`.human-use/`、凭证与生成的本机配置应忽略；忽略规则不会移除已经被 Git 跟踪的文件。不要提交机器绝对路径或私有运行信息。

Codex 的 Skill 发现和项目 hook 信任是宿主能力。setup/init 成功不表示 hook 已获信任；没有自动修改信任设置，也没有绕过权限。[Codex skills](https://learn.chatgpt.com/docs/build-skills)、[Codex hooks](https://learn.chatgpt.com/docs/hooks)

Windows 生成的 hook 通过 PowerShell EncodedCommand 执行固定 CLI 调用，避免带空格的 Node/安装路径在宿主 shell 中被误解析。编码内容只包含本地程序路径与固定参数，不包含 token 或工单输入；CLI 不执行工单提供的命令。

### 沙箱内的本地连接权限

本地服务也需要回环网络访问权限；安装成功或浏览器能打开页面，不代表 Agent 沙箱和 hook 能访问它。如果宿主已明确限制本地网络或后台进程，应通过宿主正常的执行审批机制运行对应 CLI 命令。Codex 支持时，可由 Agent 使用 `exec_command` 的 `sandbox_permissions: "require_escalated"` 请求执行该命令，说明它需要访问当前项目的本机 Human Use 服务。

`fetch failed` 若伴随 `connect EACCES` / `EPERM` 和 `127.0.0.1`，通常是权限问题；通过审批重试原命令一次，不要反复 init、重启正常服务、删 runtime 或关闭沙箱。单独的 `fetch failed` 不足以断定原因；获准后仍失败应检查实际错误和 service.log，审批不可用或被拒绝则明确报告阻塞。重试建单时沿用相同 source/request_key，避免重复。生成 hook 配置也不表示 hook 已获运行及联网权限。参见 [Codex 执行审批](https://learn.chatgpt.com/docs/agent-approvals-security)。

## Skill + API

从项目内部运行，或在任何目录传入 `--project`：

```powershell
human-use api POST /api/tickets E:/requests/ticket.json --project E:/your-project
human-use api GET /api/tickets?status=submitted --project E:/your-project
human-use api GET /api/tickets/TK-000001 --project E:/your-project
human-use api GET /api/tickets/TK-000001/attachments/附件ID --out E:/evidence/photo.png --project E:/your-project
```

请求体放在 UTF-8 JSON 文件；错误以非零退出码报告，二进制必须指定 --out。CLI 自动定位地址和凭证，在已初始化项目里可以重启停止的服务，不会创建陌生项目。完整 JSON 契约见 [API.md](API.md)；建单例见 [examples/ticket.json](../examples/ticket.json)。

安装后的 Skill 使用自己的 scripts/cli.mjs 包装器，因此 AI 无需猜测 PATH。必须检查实际回答与原始证据，再按最新提交 version/hash 验收；遇到 409 重新读现状，不盲目重试。不能替人操作人工提交界面。

## 可选 MCP

```powershell
human-use integrate codex --mcp --project E:/your-project
```

Codex 将管理片段合并到项目 `.codex/config.toml`，保留其他设置。若已有非本工具管理的 human-use MCP 项，会报冲突而非覆盖。生成的入口指向已安装 Node/CLI 和该项目；不要把项目 MCP 配成指向另一个项目的全局入口。

Claude Code 使用 `human-use integrate claude --mcp`，合并项目 `.mcp.json`，hooks 放在 `.claude/settings.local.json`。MCP 和 hook 都可在初始化时通过 --client claude 配置。配置后可能需要宿主重新加载。

stdio 入口为 `human-use mcp --project <目录>`；stdout 仅承载协议。工具为 create_ticket、list_tickets、get_ticket、read_attachment、review_ticket、cancel_ticket、get_archive、bind_session、wait_for_update、add_activity，共 10 个。图片返回原始 MCP image，其他文件返回二进制 resource。原始文件最多 20 MiB，宿主可能有更低限制。

MCP 与 Skill 共用 HTTP API，没有代替人保存草稿、上传或提交的 AI 工具，也不会绕过版本与哈希验收。

## 会话绑定、活动与继续执行

SessionStart hook 根据真实 client/session_id/cwd 注册绑定，并给 AI 上下文提供 binding_id。AI 建单携带它，才能把人工事件路由回本会话；无绑定工单仍可手动查询。不会猜测前台窗口或广播给所有聊天。

- SessionStart / UserPromptSubmit：补读人类事件，最多一页 20 条，携带准确工单、版本和哈希。
- PostToolUse：选定工具调用产生页面活动，matcher 可按客户端实际工具名调整，工具结束不表示测试通过。
- Stop：存在本会话未结束工单时，最多等待 20 秒；有人工提交/阻塞/恢复事件则请求继续，否则正常退出。stop_hook_active 防止循环。

输出上下文后才确认绑定游标；确认不代表模型看完证据。事件持久化、external_id 去重和监听租约保持原有契约。离线或超时不丢人工提交，下一轮可补读。

Codex 完全空闲后，异步 hook 不会自行启动一轮；基础方案依靠 Stop 等待窗口或下一轮补读。[官方说明](https://learn.chatgpt.com/docs/hooks)

Claude 可选 `integrations/claude.rewake.hooks.json` 是 asyncRewake 实验示例；手动替换其中软件路径后，用其 Stop 替换基础 Stop，不同时启用两份 watcher。最多后台等 15 分钟，有事件退出 2，普通超时 0，脚本故障 1。尚未在真实模型会话中验收空闲唤醒，不能当作所有客户端的支持承诺。[Claude 官方说明](https://code.claude.com/docs/en/hooks)

## 独立 v0.2 服务兼容入口

原有手动 HTTP 客户端仍能设置 `HUMAN_USE_URL`、`HUMAN_USE_TOKEN_FILE` 或 `WORKORDER_DATA_DIR`，通过 tools/bridge.mjs、独立 scripts/api.mjs 或直接 mcp/server.mjs 连接。CLI 项目模式的明确 --project 优先于这些环境变量，防止串到别的服务。

手动复制旧 API Skill 的场景使用 scripts/api.mjs；新的项目引入体验应通过 npm 安装和 setup，不只复制 setup Skill。不要同时让旧服务和新项目服务使用同一 SQLite。迁移前停旧服务，按 [部署与发布](部署与发布.md)复制数据。

## 验证范围

测试覆盖原闭环、归档、事件、SSE、CLI 生命周期、项目隔离、并发 start、配置保留、Skill 包装器和迁移。安装包测试把实际 .tgz 安装到仓库外，验证命令 shim、两个项目、提交验收、归档重启和真实 MCP stdio。

Windows 本机运行记录不等于远端 Windows/Linux CI 已执行，也不等于所有 AI 产品的真实模型会话已完成验收。npm 身份、仓库和最终包名确认后才开启公开发行；市场插件与推广仍延后。
