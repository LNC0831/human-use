# Human Use 接入指南

适用版本：0.2.0。范围：本机服务、实时提醒、Skill + API、stdio MCP 和客户端 hook。推广、npm 发布、插件市场和目录提交待定。

## 启动与凭证

安装 Node.js 24+，在仓库运行 `npm start`。地址默认 http://127.0.0.1:4317，数据默认当前工作目录的 data/。升级不移动原数据、不改写旧归档；事件表从升级后的操作开始记录，不伪造历史未读。

先启动服务，再启动 AI 客户端。MCP 不会自行启动第二个服务。在启动客户端的 PowerShell 设置：

```powershell
$env:HUMAN_USE_URL = 'http://127.0.0.1:4317'
$env:HUMAN_USE_TOKEN_FILE = 'E:/path/to/HumanUse/data/api-token'
```

替换为真实绝对路径。hook 从父客户端继承环境；MCP 配置内的 env 只传给 MCP，不会设置父客户端环境。`WORKORDER_DATA_DIR` 仍受支持；跨项目时优先指定凭证文件。接入失败请检查服务、端口和凭证是否对应。不要公开 token。

## Skill + API：无需 MCP

复制整个 [skills/human-use](../skills/human-use) 目录到目标客户端，保留 SKILL.md、scripts/ 和 references/。例如 Codex 项目级 `.agents/skills/human-use/`，Claude Code 项目级 `.claude/skills/human-use/`，重新加载后调用 human-use。也可先让客户端读取仓库内 SKILL.md 试用。

Skill 脚本只用 Node 内置模块，无需 npm install，不依赖原仓库位置。它指导建单、等待、读取原始证据、按版本与哈希验收。仓库内 Bridge 包装同一脚本：

```powershell
node tools/bridge.mjs POST /api/tickets examples/ticket.json
node tools/bridge.mjs GET /api/tickets?status=submitted
node tools/bridge.mjs GET /api/tickets/TK-000001
```

仓库外用复制后的 `scripts/api.mjs` 绝对路径，参数相同。POST 请求体放入 UTF-8 JSON 文件；下载原图和 ZIP 加 `--out <文件>`。错误以非零退出码明确报告。Skill 不代替人勾选或提交，不应仅凭附件元数据通过验收。

## MCP

仓库中先执行 `npm ci --ignore-scripts`，安装锁定的官方 MCP SDK 与 Zod。核心 HTTP 服务和 Skill 无需这些依赖。入口 `mcp/server.mjs` 使用 stdio，stdout 仅承载协议消息。

配置样例：[通用 mcpServers JSON](../integrations/mcp.example.json)、[Codex TOML](../integrations/codex.mcp.toml)。替换绝对路径后合并到自己的客户端配置，不要覆盖已有设置。不同客户端的配置根节点可能不同。

Claude Code 的项目 MCP 配置为项目根目录 `.mcp.json`；Codex TOML 可合并到 `~/.codex/config.toml` 或受信任项目的 `.codex/config.toml`。重启对应客户端后确认已连接 Human Use，再创建首张工单。

| 工具 | 行为 |
| --- | --- |
| create_ticket / list_tickets / get_ticket | 建单、查询、读取完整提交 |
| read_attachment | 校验并返回原始文件，图片为 MCP image，其他文件为二进制 resource |
| review_ticket / cancel_ticket | 按提交版本与哈希验收，或按 revision 取消 |
| get_archive | 校验归档并返回本机下载地址 |
| bind_session | 按真实 client、session_id、cwd 注册路由 |
| wait_for_update | 等待最多 25 秒的人类事件，超时 waiting=true |
| add_activity | 页面展示真实 AI 动作，不代替验收 |

没有代替人保存草稿、上传或提交的 MCP 工具。原始附件仍使用 20 MiB 上传上限，客户端可能有更低的消息或图像限制；必要证据无法读取时，应保留待验收。

## 会话绑定与 hook

hook 不依赖 MCP。SessionStart 登记 `client + session_id + cwd`，向上下文提供 binding_id；**AI 建单必须携带该 binding_id**，才能把人类事件路由回这个会话。无绑定工单可手动查询。不会猜测前台窗口或广播到其他会话。

配置见 [Codex hooks](../integrations/codex.hooks.json)、[Claude hooks](../integrations/claude.hooks.json)。替换带引号的绝对路径，合并到客户端并启用其信任设置。Windows 路径可写为 `E:/path/with spaces/...`。本轮未修改任何全局客户端设置。

Codex 可使用 `~/.codex/hooks.json` 或受信任项目的 `.codex/hooks.json`；Claude 合并到 `.claude/settings.local.json`（本机项目）或 `~/.claude/settings.json`（全部项目）。只选一个安装层，避免同一 hook 重复注册。首次会话应能看到 Human Use binding_id；建单后可读取工单确认 binding_id 一致。

- SessionStart / UserPromptSubmit：绑定并补读尚未交给 hook 的人类事件，给出工单 ID、版本和哈希。
- 选定 PostToolUse：向本会话未结束工单添加工具调用提示。matcher 按客户端实际工具名调整；工具结束不代表测试通过。
- Stop：存在本会话未结束工单时，最多等 20 秒；收到人类提交、阻塞或恢复事件时请求继续，否则正常结束。stop_hook_active 防止停止回调循环。

每个绑定独立确认游标，输出上下文后才确认；确认仅表示脚本输出，**不表示模型已经读取或完成验收**。事件持久化、活动 external_id 去重、监听租约防止并发 watcher。超时或离线不丢提交，下一轮可以补读。

### 续跑边界

Codex 可在 Stop 尚未结束的等待窗口请求继续，完全空闲后需下一次用户轮次补读。异步 hook 输出不会自行启动空闲轮次。本版不接管桌面聊天，也未增加 app-server 调度器。[Codex 官方 hooks](https://learn.chatgpt.com/docs/hooks)

Claude 基础配置同样采用有上限的同步 Stop。支持 asyncRewake 的客户端可选择 [实验后台配置](../integrations/claude.rewake.hooks.json)：用其 Stop 替换基础 Stop，保留 SessionStart 等配置；最多后台等 15 分钟，有事件以退出码 2 输出提醒，正常超时 0，脚本故障 1。不要同时启用两个 Stop watcher。[Claude 官方 hooks](https://code.claude.com/docs/en/hooks)

本机 Claude 2.1.150 二进制可找到 asyncRewake 字段；脚本协议与退出码已测，但未执行真实模型轮次的空闲唤醒验收，故后台配置标为实验。Codex CLI 0.155.1 只核对版本，不能据此声称所有桌面宿主都支持 hooks。普通 MCP 等待工具也不保证跨客户端主动唤醒。

## 页面与验证

同源 SSE 实时更新，断线按 event ID 补读；侧栏未读数量、工单“新 / 有更新”与待处理状态分开。查看详情后记录已读，刷新保留。正在填写或有未保存修改时不重建表单，提示“查看最新内容”；重新载入仍需确认。已读和活动不改动提交快照或旧归档。

`npm test` 覆盖原闭环、归档、事务回滚、未读、重启补读、SSE 路由与中断清理、独立复制的 Skill、官方 SDK stdio 客户端、原图字节、退回与版本验收、hook 路由/去重/超时/退出码。真实协议测试不等于已在每个 AI 产品的模型会话中验收。

Skill 目录规则参考 [Codex skills](https://learn.chatgpt.com/docs/build-skills)、[Claude skills](https://code.claude.com/docs/en/skills)。发布包、商店封装与推广均待定。
