# 部署、项目数据与 npm 发布

v0.3.0 采用 npm 分发软件本体与 CLI，Codex 使用用户级 Skill 发现能力。软件安装一次，每个项目单独初始化、启动服务并保存记录。默认 Skill + API；MCP 按需启用。worktree 共享、系统自启动、插件市场和推广留待后续。

## 当前发行状态

源码仓库为 [LNC0831/human-use](https://github.com/LNC0831/human-use)。正式 npm 包名和发布账号待维护者确认，package.json 暂保留 `private: true`，防止以临时名称误发布。CI 的实际执行结果可在仓库 Actions 中查看。

Node.js 24+ 为运行前提。尚未提供免 Node 的 EXE、便携包或自动更新服务。首发前可本地执行 `npm pack`，再用 `npm install -g ./human-use-0.3.0.tgz` 安装生成的文件。

## 首次安装和日常使用

正式包名确认后，安装说明替换为 `npm install -g @your-scope/human-use`。其中 your-scope 是待替换的账号示意，不是现有发布地址。

安装后执行一次：

```powershell
human-use setup codex
```

命令将初始化 Skill 和协作 Skill 安装到用户的 `~/.agents/skills/`。CLI 用安装标记区分自己管理的 Skill，遇到同名的用户自建 Skill 会报错，不覆盖。可用 `--skills-dir <目录>` 在隔离环境验证。Skill 包含指向已安装 CLI 的包装脚本，不依赖当前项目中的 node_modules。

Codex 可能需要新开会话才能发现新 Skill。之后在项目中说“给当前项目引入 Human Use”，AI 应调用：

```powershell
human-use init --project E:/your-project --client codex
```

命令创建配置、合并项目说明和忽略规则、生成项目 hooks、启动或复用后台服务，并打开默认浏览器。`--no-open` 适合无界面测试；`--no-hooks` 只初始化 Skill + API。不会在 init 时安装全局 Skill、修改全局 Codex 设置或发布任何内容。

所有管理命令输出 JSON。API 凭证不输出；地址、路径和集成 notice 都在结果中。浏览器打开失败会明确报错，服务仍运行，可以读取 status 中的 URL 手动打开。

## 项目与服务

```text
your-project/
  human-use.json            项目配置，可提交 Git
  AGENTS.md                 追加 Human Use 管理片段，保留原内容
  .gitignore                追加本机数据和配置的忽略项
  .human-use/               本机私有目录，整体忽略
    workorders.sqlite       工单、事件、已读、绑定
    attachments/            原始附件
    archives/<sha256>/      冻结工单包
    api-token               本项目凭证
    runtime.json            服务 URL、PID、实例 ID 和版本
    service.log             后台日志，不打印 token
```

CLI 从指定目录向上查找最近的 human-use.json；AI 应明确传入当前项目根目录，避免在错误目录初始化。普通文件夹可用。各目录的数据独立，不做 Git/worktree 合并。项目配置被复制到另一目录时，也不会复用原目录的运行实例。

每个项目一个后台进程，监听 127.0.0.1，由系统分配空闲端口。同一份已安装程序服务多个项目。start 有启动锁，重复或并发 start 复用已就绪实例。管理命令通过凭证、项目 ID、目录和实例 ID 核对服务；stop 调用受认证的控制接口，不按任意 PID 杀进程。

```powershell
human-use status --project E:/your-project
human-use stop --project E:/your-project
human-use start --project E:/your-project
human-use open --project E:/your-project
```

关闭浏览器或 Codex 不会自动停止后台服务；stop 明确停止，电脑重启后需要再次 start。CLI API 和 MCP 在已初始化项目里能启动已停止服务，不会擅自初始化陌生目录。版本不一致时明确要求停止并重启。

若初始化进程被强制终止并遗留 start.lock，CLI 会报告路径；确认报错所示的原进程已结束后移除该锁再启动。不会自动争抢旧锁或按运行信息中的任意 PID 杀进程。

## 更新与卸载

更新前停止相关项目的服务，再执行对应包的 `npm install -g <正式包名>@<版本>`。更新后执行 `human-use setup codex` 刷新用户级包装脚本，重新 start 项目；需要时重新 integrate 更新项目接入配置。不做运行中热更新。

卸载前同样先停止服务，再执行 `npm uninstall -g <正式包名>`。项目数据保留，不随 npm 卸载删除。用户级 Skill 不会由 npm 卸载脚本自动删除；可按 setup 输出的两个路径手动移除本工具管理的 Skill。备份项目数据时先停止服务，复制整个 .human-use/，凭证也属于私有备份。

## 迁移 v0.2 数据

先停止旧服务，再执行迁移，目标项目的 .human-use/ 必须不存在或为空：

```powershell
human-use migrate --from E:/old-human-use/data --project E:/your-project
human-use init --project E:/your-project
```

迁移复制数据库、附件和归档，不删除源目录，不覆盖已有项目数据。先校验复制的数据库，再将其作为目标数据目录；目标会生成独立凭证。旧归档文件不改写，哈希不变。旧的手动客户端需改用 CLI 或目标凭证。

迁移要求源服务离线。v0.2 无运行登记，CLI 无法仅凭目录可靠判断其服务是否仍打开，操作者必须先停掉它。校验失败会保留临时副本，错误中给出目录，便于检查。

## Tag、Release 与 CI

- 包版本与 tag 对应，例如 `0.3.0` / `v0.3.0`，预发布 `0.3.0-beta.1` / `v0.3.0-beta.1`。
- 补丁用于兼容修复；次版本用于功能。0.x 中的接口或数据不兼容变更必须写清迁移说明。归档格式独立标识，升级不重写旧包。
- 已发布 tag 和同版本包不替换，修复发新版本。
- PR / main：Windows 与 Linux 执行内置测试，并打出真实 npm 包，安装到仓库外验证命令入口、Skill、项目隔离、归档、重启和 MCP。
- tag：先校验版本，再复用上述 CI；通过后生成 .tgz、SHA256SUMS.txt 和 Draft GitHub Release。
- 维护者检查并公开 GitHub Release，随后手动触发 Publish npm package，输入同一个 tag。流水线下载该 Release 附件，核对校验值，再发布这个经过检查的文件，避免现场重新打包。
- 稳定版本使用 npm latest，预发布使用 next。

package.json 的 files 是发布白名单；.gitignore 不能代替包内容检查。CI 验证包内没有工单、凭证、SQLite、日志或本机运行信息。

## 首次公开发布前的维护者配置

1. 确认 npm 账号/作用域及最终包名，同步 package.json 和锁文件的根包名称；命令入口始终为 human-use。
2. GitHub 仓库已配置为 LNC0831/human-use，`repository.url` 与其对应；如转移仓库，需同步此字段。
3. 首次发布可由维护者本机 npm login 后发布已检查的 .tgz。确认身份与名称后才改为 private:false；当前不提交 token。
4. 包存在后，在 npm 包设置建立 GitHub trusted publisher，绑定 owner、repository、`publish.yml`、environment `npm`，允许直接 publish。GitHub 中建立 npm environment，并按需要设置审核人。
5. 后续由 GitHub 托管 runner 使用 OIDC 发布，不在仓库保存长期 npm token。检查 runner npm 版本满足官方要求。

GitHub 仓库公开不等于 npm 已发布；npm 身份配置、包名确认和首发需要维护者完成。tag 流程可以生成 GitHub Release 草稿，npm 发布工作流仍会检查发布开关与仓库身份。[npm trusted publishing](https://docs.npmjs.com/trusted-publishers/)
